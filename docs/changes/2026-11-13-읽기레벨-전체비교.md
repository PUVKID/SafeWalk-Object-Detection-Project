+## LEVEL 1 · 실제 기능과 동작 범위

+**물체 탐지와 실제 보행 위험 판정 성능은 다릅니다.** 시험 결과로 다음 시작 모델을 고르는 구성이라 같은 시험의 최종 수치를 독립 평가로 보지 않습니다. 원본 분할을 합쳐 재분할하고 내용 중복 검출이 없으며 이름 매핑 실패 시 ID 정렬 fallback을 확인해야 합니다.

+설치 셀을 실행한 뒤 GPU 확인과 자료 목록·버전·이용 조건을 확인합니다. COCO 자료를 받는 갈래는 `fiftyone.zoo`가 필요하지만 첫 설치 목록에는 `fiftyone`이 없습니다. 웹캠 창을 보려면 GUI 표시 환경도 필요합니다. 화면이 없는 서버용 `opencv-python-headless`만 설치한 상태와 구분합니다. Linux CUDA 경로를 바꾸는 셀은 Windows에서 그대로 적용할 수 없습니다.
+
+[이 항목의 전체 조건·원문](#source-section-10)
+
+### LEVEL 1 · 데이터 구성과 클래스
+
+공통 번호는 0 자전거(bicycle), 1 킥보드(kickboard), 2 볼라드(bollard), 3 자동차(car), 4 오토바이(motorcycle), 5 계단(stairs), 6 횡단보도(crosswalk), 7 보행자(people)입니다. 자료마다 같은 물체 이름이 다를 수 있어 `class_map`으로 이름을 공통 번호에 연결합니다.
+
+라벨은 물체 종류와 사각형 위치·크기를 적는 bbox 5항목만 사용하며, 물체 윤곽선을 여러 점으로 표시하는 세그멘테이션 줄은 제외합니다. 이름이 전혀 맞지 않으면 정렬된 원본 번호와 대상 번호를 순서대로 연결하는 fallback이 있습니다. 이 순서가 실제 물체의 뜻과 다르면 잘못된 정답을 학습하므로 출력된 매핑을 직접 확인해야 합니다. 원래 train/valid/test를 합쳐 다시 나누며 영상 내용의 중복 탐지는 없습니다. 파일이 나뉘었다고 같은 사진의 중복까지 제거된 것은 아닙니다.
+
+[이 항목의 전체 조건·원문](#source-section-11)
+
+### LEVEL 1 · 실제 학습 설정
+
+자료를 세 묶음으로 나눕니다. 학습은 모델을 바꾸는 데, 검증은 학습 중 상태를 확인하는 데, 시험은 결과를 재는 데 사용합니다. 볼라드와 횡단보도는 먼저 각각 **100장과 해당 종류 영상 수의 15% 중 더 적은 수**를 시험에 배정합니다(`min(100, 15%)`). 그 뒤 남은 영상의 74%를 학습, 21%를 검증, 나머지를 추가 시험으로 나눕니다. 따라서 제목의 7:2:1과 실제 최종 비율이 같지 않으며 언제나 시험 100장이 확보되는 것도 아닙니다.
+
+Phase 1은 YOLOv8x 모델로 각 종류를 먼저 학습하는 단계입니다. 이미지 크기는 640, 학습 갱신 방식은 AdamW, 반복은 종류마다 15~40 epoch입니다. epoch는 학습 자료를 한 차례 순회하는 단위입니다. Phase 2는 Phase 1의 시험 성적을 보고 고른 모델에서 시작해 전체 종류를 150 epoch 학습하도록 구성합니다. 시작 학습률 `lr0=0.0005`와 `patience=0`도 이 단계 설정입니다. 같은 시험을 모델 선택에도 썼으므로 마지막 시험값은 처음 보는 독립 시험 성적이 아닙니다.
+
+사진에서 물체를 찾을 때의 조건은 학습 반복과 다릅니다. `conf=0.4`는 남길 예측의 점수 기준, `IoU=0.45`는 겹친 상자를 정리하는 기준이며 이미지 640과 최대 50개 탐지를 사용합니다. 속도 측정은 무작위 사진 한 장으로 준비 추론 10회를 먼저 하고 100회 반복합니다. 이 반복 수는 학습 횟수나 보행 안전 시험 횟수가 아닙니다. 실제 결과는 해당 실행의 `args.yaml`과 `results.csv`에서 precision·recall·mAP50·mAP50–95와 함께 읽습니다.
+
+[이 항목의 전체 조건·원문](#source-section-12)

+## 노트북 셀과 실험 기록의 연결

+### 실제 학습 설정
+
+| 단계 | 코드 설정 |
+| :--- | :--- |
+| 병합 | YOLO bbox의 5개 항목 형식을 유지하고 세그멘테이션 라인을 제외 |
+| 테스트 확보 | 볼라드·횡단보도 각각 `min(100, 해당 이미지 수의 15%)`를 우선 배정 |
+| 나머지 분할 | 강제 테스트 배정 후 남은 이미지의 74% 학습·21% 검증·나머지 테스트 |
+| Phase 1 | 클래스별 15~40 epoch, YOLOv8x, 이미지 640, AdamW |
+| Phase 2 | 선택된 Phase 1 모델을 시작점으로 전체 클래스 150 epoch, `lr0=0.0005`, `patience=0` |
+| 최종 평가 | `split="test"`, mAP50·mAP50-95·precision·recall |
+| 추론 설정 | `conf=0.4`, `iou=0.45`, 이미지 640, 최대 탐지 50개 |
+| 속도 측정 | 무작위 이미지 한 장으로 준비 추론 10회 뒤 반복 추론 100회 |
+
+분할 셀의 제목은 7:2:1이지만 실제 비율은 위의 강제 테스트 배정과 74:21 분할에 따라 달라집니다. 테스트 이미지를 항상 100장 확보하는 것도 아닙니다. 또한 Phase 1의 테스트 평가값으로 Phase 2 시작 모델을 선택하므로, 같은 테스트셋의 최종 값에는 모델 선택의 영향이 포함됩니다.
+
+데이터 이름 매핑에 일치 항목이 하나도 없을 때는 원본 ID와 대상 ID의 정렬 순서로 연결하는 fallback이 있습니다. 해당 경로가 쓰였는지 출력된 ID 매핑을 확인해야 합니다. 데이터 원본별 train·valid·test는 한데 모아 재분할하며, 이미지 내용의 중복 검출은 이 분할 코드에 없습니다.
+
+`SafeWalkDetector`는 자전거·킥보드·자동차·오토바이 탐지에 주의 문구를 표시합니다. 거리를 계산하거나 충돌 위험을 예측하는 로직은 아닙니다. TensorRT 변환은 CUDA 환경에서 FP16 엔진을 생성하는 별도 단계이며, 속도 비교는 자신이 실행한 장치의 결과를 사용합니다.
+
+노트북에는 목표 정확도와 처리속도를 설정했습니다. 실제 보행 안전을 평가하려면 장치별 처리속도와 클래스별 탐지 성능, 실제 보행 환경의 검증이 필요합니다.

+## 노트북 셀과 실험 기록의 연결
+
+데이터 다운로드→원본 클래스명/ID 매핑→YOLO bbox 병합→분할→클래스별 학습→시작 모델 선택→전체 미세조정→평가/추론/내보내기의 순서입니다.
+

+### 실제 학습 설정
+
+| 단계 | 코드 설정 |
+| :--- | :--- |
+| 병합 | YOLO bbox의 5개 항목 형식을 유지하고 세그멘테이션 라인을 제외 |
+| 테스트 확보 | 볼라드·횡단보도 각각 `min(100, 해당 이미지 수의 15%)`를 우선 배정 |
+| 나머지 분할 | 강제 테스트 배정 후 남은 이미지의 74% 학습·21% 검증·나머지 테스트 |
+| Phase 1 | 클래스별 15~40 epoch, YOLOv8x, 이미지 640, AdamW |
+| Phase 2 | 선택된 Phase 1 모델을 시작점으로 전체 클래스 150 epoch, `lr0=0.0005`, `patience=0` |
+| 최종 평가 | `split="test"`, mAP50·mAP50-95·precision·recall |
+| 추론 설정 | `conf=0.4`, `iou=0.45`, 이미지 640, 최대 탐지 50개 |
+| 속도 측정 | 무작위 이미지 한 장으로 준비 추론 10회 뒤 반복 추론 100회 |
+
+분할 셀의 제목은 7:2:1이지만 실제 비율은 위의 강제 테스트 배정과 74:21 분할에 따라 달라집니다. 테스트 이미지를 항상 100장 확보하는 것도 아닙니다. 또한 Phase 1의 테스트 평가값으로 Phase 2 시작 모델을 선택하므로, 같은 테스트셋의 최종 값에는 모델 선택의 영향이 포함됩니다.
+
+데이터 이름 매핑에 일치 항목이 하나도 없을 때는 원본 ID와 대상 ID의 정렬 순서로 연결하는 fallback이 있습니다. 해당 경로가 쓰였는지 출력된 ID 매핑을 확인해야 합니다. 데이터 원본별 train·valid·test는 한데 모아 재분할하며, 이미지 내용의 중복 검출은 이 분할 코드에 없습니다.
+
+`SafeWalkDetector`는 자전거·킥보드·자동차·오토바이 탐지에 주의 문구를 표시합니다. 거리를 계산하거나 충돌 위험을 예측하는 로직은 아닙니다. TensorRT 변환은 CUDA 환경에서 FP16 엔진을 생성하는 별도 단계이며, 속도 비교는 자신이 실행한 장치의 결과를 사용합니다.
+
+노트북에는 목표 정확도와 처리속도를 설정했습니다. 실제 보행 안전을 평가하려면 장치별 처리속도와 클래스별 탐지 성능, 실제 보행 환경의 검증이 필요합니다.

+## 노트북 셀과 실험 기록의 연결
+
+데이터 다운로드→원본 클래스명/ID 매핑→YOLO bbox 병합→분할→클래스별 학습→시작 모델 선택→전체 미세조정→평가/추론/내보내기의 순서입니다.
+
+기본 노트북은 이 흐름의 구현이고 pbl2-main은 설정 YAML·실행 노트북·에폭 CSV를 묶은 실험 자료입니다. 같은 파일명이라도 이전 도커 버전과 현재 노트북을 구분합니다.

+
+볼라드와 횡단보도 각각에 min(100,15%) 테스트를 먼저 배정한 뒤 남은 영상을 74%/21%/잔여로 train/val/test에 나눕니다.
+
+Phase1의 테스트 성적으로 Phase2 시작 모델을 선택하므로 같은 테스트의 최종 수치는 선택과 독립된 평가가 아닙니다. 모델 이름과 목표값을 보행 안전 성과로 해석하지 않습니다.

+
+COCO 분기는 fiftyone이 필요하고 웹캠 GUI에는 headless OpenCV와 다른 표시 환경이 필요합니다. 병합·분할 셀이 merged/processed/per_class를 다시 만들기 때문에 전용 실험 경로와 이전 결과 보존을 먼저 확인합니다. 위험 문구는 탐지 객체 종류에 따른 안내이며 거리나 충돌 확률을 계산하지 않습니다.

+| 나머지 분할 | 강제 테스트 배정 후 남은 이미지의 74% 학습·21% 검증·나머지 테스트 |
+| Phase 1 | 클래스별 15~40 epoch, YOLOv8x, 이미지 640, AdamW |
+| Phase 2 | 선택된 Phase 1 모델을 시작점으로 전체 클래스 150 epoch, `lr0=0.0005`, `patience=0` |
+| 최종 평가 | `split="test"`, mAP50·mAP50-95·precision·recall |
+| 추론 설정 | `conf=0.4`, `iou=0.45`, 이미지 640, 최대 탐지 50개 |
+| 속도 측정 | 무작위 이미지 한 장으로 준비 추론 10회 뒤 반복 추론 100회 |
+
+분할 셀의 제목은 7:2:1이지만 실제 비율은 위의 강제 테스트 배정과 74:21 분할에 따라 달라집니다. 테스트 이미지를 항상 100장 확보하는 것도 아닙니다. 또한 Phase 1의 테스트 평가값으로 Phase 2 시작 모델을 선택하므로, 같은 테스트셋의 최종 값에는 모델 선택의 영향이 포함됩니다.
+
+데이터 이름 매핑에 일치 항목이 하나도 없을 때는 원본 ID와 대상 ID의 정렬 순서로 연결하는 fallback이 있습니다. 해당 경로가 쓰였는지 출력된 ID 매핑을 확인해야 합니다. 데이터 원본별 train·valid·test는 한데 모아 재분할하며, 이미지 내용의 중복 검출은 이 분할 코드에 없습니다.
+
+`SafeWalkDetector`는 자전거·킥보드·자동차·오토바이 탐지에 주의 문구를 표시합니다. 거리를 계산하거나 충돌 위험을 예측하는 로직은 아닙니다. TensorRT 변환은 CUDA 환경에서 FP16 엔진을 생성하는 별도 단계이며, 속도 비교는 자신이 실행한 장치의 결과를 사용합니다.
+
+노트북에는 목표 정확도와 처리속도를 설정했습니다. 실제 보행 안전을 평가하려면 장치별 처리속도와 클래스별 탐지 성능, 실제 보행 환경의 검증이 필요합니다.

+매핑 계약은 이름 기반 통합→전부 불일치 시 정렬 ID fallback이며, bbox 5항목과 세그멘테이션 제외로 입력 형식을 제한합니다. 공통 ID 0~7은 bicycle·kickboard·bollard·car·motorcycle·stairs·crosswalk·people 순서입니다. fallback은 구문상 연결을 만들 뿐 의미 동등성을 입증하지 않으므로 원본 라벨·매핑·분포를 함께 검토합니다. 원래 분할 통합과 내용 중복 검출 부재는 평가 누수 검토의 제약입니다.

+[이 항목의 전체 조건·원문](#source-section-11)
+
+### LEVEL 4 · 실제 학습 설정
+
+분할 프로토콜은 특정 두 클래스에 `min(100, 15%)` 시험을 선배정한 뒤 나머지를 74%/21%/잔여로 분리합니다. 제목 7:2:1을 구현 비율로 간주하면 표본 수와 평가 분모가 달라집니다. Phase 1의 YOLOv8x·640·AdamW·15~40 epoch와 Phase 2의 150 epoch·`lr0=0.0005`·`patience=0`은 클래스별 초기 학습과 통합 미세조정의 서로 다른 예산입니다. Phase 1 시험값으로 시작 모델을 선택해 같은 시험의 최종값에 선택 편향이 남습니다. `args.yaml/results.csv` 계보와 precision·recall·mAP50·mAP50–95를 대조합니다. 추론 conf 0.4·IoU 0.45·640·max_det 50과 준비 10회/속도 100회는 예측 필터·후처리·시간 측정의 계약이며 학습 설정과 분리합니다.

+분할 셀의 제목은 7:2:1이지만 실제 비율은 위의 강제 테스트 배정과 74:21 분할에 따라 달라집니다. 테스트 이미지를 항상 100장 확보하는 것도 아닙니다. 또한 Phase 1의 테스트 평가값으로 Phase 2 시작 모델을 선택하므로, 같은 테스트셋의 최종 값에는 모델 선택의 영향이 포함됩니다.
+
+데이터 이름 매핑에 일치 항목이 하나도 없을 때는 원본 ID와 대상 ID의 정렬 순서로 연결하는 fallback이 있습니다. 해당 경로가 쓰였는지 출력된 ID 매핑을 확인해야 합니다. 데이터 원본별 train·valid·test는 한데 모아 재분할하며, 이미지 내용의 중복 검출은 이 분할 코드에 없습니다.
+
+`SafeWalkDetector`는 자전거·킥보드·자동차·오토바이 탐지에 주의 문구를 표시합니다. 거리를 계산하거나 충돌 위험을 예측하는 로직은 아닙니다. TensorRT 변환은 CUDA 환경에서 FP16 엔진을 생성하는 별도 단계이며, 속도 비교는 자신이 실행한 장치의 결과를 사용합니다.
+
+노트북에는 목표 정확도와 처리속도를 설정했습니다. 실제 보행 안전을 평가하려면 장치별 처리속도와 클래스별 탐지 성능, 실제 보행 환경의 검증이 필요합니다.

+강제 시험 `min(100, 15%)`의 클래스별 분모와 잔여 74/21/나머지 분할을 재계산하고 Phase 1 시험에 기반한 Phase 2 초기화 선택의 평가 재사용을 명시합니다. Phase 1 YOLOv8x·640·AdamW·15~40 epoch, Phase 2 150 epoch·`lr0=0.0005`·`patience=0`을 실제 `args.yaml`과 `results.csv`에 결합해 지표를 해석합니다. conf 0.4·IoU 0.45·640·max_det 50은 추론/상자 후처리 조건, 무작위 한 장 준비 10회/100회 반복은 장치별 속도 측정 조건입니다. 이 계약의 통과와 mAP50·mAP50–95·precision·recall은 실제 보행 위험 예측·거리 추정·충돌 확률 검증을 대신하지 않습니다.

+### 실제 학습 설정
+
+| 단계 | 코드 설정 |
+| :--- | :--- |
+| 병합 | YOLO bbox의 5개 항목 형식을 유지하고 세그멘테이션 라인을 제외 |
+| 테스트 확보 | 볼라드·횡단보도 각각 `min(100, 해당 이미지 수의 15%)`를 우선 배정 |
+| 나머지 분할 | 강제 테스트 배정 후 남은 이미지의 74% 학습·21% 검증·나머지 테스트 |
+| Phase 1 | 클래스별 15~40 epoch, YOLOv8x, 이미지 640, AdamW |
+| Phase 2 | 선택된 Phase 1 모델을 시작점으로 전체 클래스 150 epoch, `lr0=0.0005`, `patience=0` |
+| 최종 평가 | `split="test"`, mAP50·mAP50-95·precision·recall |
+| 추론 설정 | `conf=0.4`, `iou=0.45`, 이미지 640, 최대 탐지 50개 |
+| 속도 측정 | 무작위 이미지 한 장으로 준비 추론 10회 뒤 반복 추론 100회 |
+
+분할 셀의 제목은 7:2:1이지만 실제 비율은 위의 강제 테스트 배정과 74:21 분할에 따라 달라집니다. 테스트 이미지를 항상 100장 확보하는 것도 아닙니다. 또한 Phase 1의 테스트 평가값으로 Phase 2 시작 모델을 선택하므로, 같은 테스트셋의 최종 값에는 모델 선택의 영향이 포함됩니다.
+
+데이터 이름 매핑에 일치 항목이 하나도 없을 때는 원본 ID와 대상 ID의 정렬 순서로 연결하는 fallback이 있습니다. 해당 경로가 쓰였는지 출력된 ID 매핑을 확인해야 합니다. 데이터 원본별 train·valid·test는 한데 모아 재분할하며, 이미지 내용의 중복 검출은 이 분할 코드에 없습니다.
+
+`SafeWalkDetector`는 자전거·킥보드·자동차·오토바이 탐지에 주의 문구를 표시합니다. 거리를 계산하거나 충돌 위험을 예측하는 로직은 아닙니다. TensorRT 변환은 CUDA 환경에서 FP16 엔진을 생성하는 별도 단계이며, 속도 비교는 자신이 실행한 장치의 결과를 사용합니다.
+
+노트북에는 목표 정확도와 처리속도를 설정했습니다. 실제 보행 안전을 평가하려면 장치별 처리속도와 클래스별 탐지 성능, 실제 보행 환경의 검증이 필요합니다.
